## A. Mechanism and theory

### A1. Theory: why high order drives saturation (writing, ~1.5 weeks)
Turn the saturation result from an observation into a derived prediction.
- **Extremality lemma.** Let a readout be ∏_{j∈S} cos(π tanh z_j). For |readout| ≥ 1−ε, every
  factor in S must sit within O(√(ε)) of ±1. Each factor then sits at z_j ≈ 0 (cos = +1) or at
  |z_j| → ∞ (cos = −1). A large negative readout needs an odd number of saturated factors, and
  the more readouts each coordinate enters (higher order and overlap), the more readouts constrain it
  to these extremes. Result: the share of coordinates forced toward saturation rises with order and
  overlap. This also accounts for the star vs window result.
- **Absorbing-state lemma.** sech²(z_j) gives a saturated coordinate near-zero gradient from
  every readout, so it stays saturated. Combined with the lemma above, this is a "saturation trap".
- **Toy model, solved exactly or numerically.** Use a linear backbone z = Wx on a Gaussian mixture
  with K classes, a fixed product-readout head of order m, and gradient flow. Predict the saturated
  fraction and the linear-probe accuracy of Wx as functions of m and overlap. Check that the toy model
  reproduces the ordering, the star > window effect and the ring-free match. This takes minutes on CPU.
- The output is a proposition and toy-model figure for the main text, with proofs in the appendix.
  Prop. `prop:atten` stays as the attenuation half.

### A2. Forward-identical intervention: straight-through tanh (≈ 44 runs)
This is the cleanest test of the saturation route. Keep the forward pass exactly the same, and in the
backward pass replace sech²(z_j) with 1 (or with max(sech², 0.19) as a floor). The function class,
fit target and initialization stay the same, so only the gradient at saturated coordinates changes.
- Heads: default, last-ring, ring-free and default-products (classical), on CIFAR-10/4,000.
- Pre-registered prediction: recovers at least as much as the saturation penalty (≥ +1.7 default,
  ≥ +6 last-ring), with little change for ring-free.
- Interpretation: success means the gradient trap is the route. Failure means saturated forward
  values (lost information) are the route, which the penalty helps with but the straight-through
  estimator does not. Either result narrows the mechanism. This complements the earlier
  attenuation-floor test (`cifar_floor`), which removed the *other* factors.

### A3. Two-way manipulation: induce saturation in the ring-free head (≈ 22 runs)
So far saturation has only been reduced. Inducing it in the order-1 head tests the reverse direction.
Use a penalty that pushes |tanh z| above 0.9 toward a target fraction (0.3 and 0.5, matching the
default and last-ring heads).
- Prediction: probe accuracy drops toward the default and last-ring values in proportion to the
  fraction induced. Report the dose-response.

### A4. Non-saturating encoding (≈ 33 runs plus layouts)
Every encoding tested so far is tanh-bounded. Use R_y(z_j) with z_j unbounded (optionally z_j scaled
by a learned or fixed constant). Identity (1) still holds with cos z_j, but the encoding has no
saturation trap.
- Prediction, if saturation is the main route: the order–probe slope flattens markedly (pre-register a
  threshold, e.g. |Spearman| < 0.5 or a slope under half the tanh slope across 4 layouts). If the
  slope survives, the attenuation route or the function class is doing the work. Both outcomes are
  reportable.
- Watch for a confound: periodicity makes the coordinate's sign ambiguous. Probe on (cos z, sin z) as
  well as z.

### A5. Dynamics (re-analysis plus one logging run per head)
Log saturation, effective dimension and the probe every 5 epochs for the default, last-ring and
ring-free heads. Check whether saturation onset comes *before* the probe gap opens. This is
time-ordering evidence for mediation and is cheap.

### A6. Calibrated descriptor across widths (theory from A1, then 16 qubits, ≈ 40 runs)
Use A1 to derive a width-normalized quantity. Candidates are the expected product signal
Σ_k ∏_{j∈S_k} E[cos²], or the saturation-pressure count from the extremality lemma. Fit it on 8
qubits, check it retrospectively on 12, then pre-register a prediction at 16 qubits, where the
statevector is 65K amplitudes and still cheap. This answers limit 3.

## B. Generality

### B1. Order without entanglement: observable-defined order (≈ 33 runs)
Take the **ring-free** circuit and measure products of Paulis, Z_kZ_{k+1} or weight-3 strings, instead
of single Z_k. This gives order 2 or 3 with **no entangling gates at all**.
- Prediction: probe accuracy falls on the same order trend as the CNOT circuits.
- The classical product heads already show order without a circuit. B1 adds the matched version:
  the same quantum circuit, parameters and rotations, with only the observable changed. Together with
  `pairs` (entanglement without order), it gives both directions of the separation inside the VQC.

### B2. Another gate family: CZ / controlled-rotation rings (≈ 33 runs) — top priority
CZ commutes with Z, so a CZ ring has zero-rotation order **1**, yet it entangles, and its trained
effective order (`scripts/effective_order.py`) is above 1.
- Pre-register: CZ ring probes close to ring-free at default initialization. Effective order at
  trained rotations predicts any residual cost.
- Optionally add a StronglyEntanglingLayers-style ansatz (CRZ rings) as a third family.

### B3. Data re-uploading (code exists: `--reupload_mode light|strong`) (≈ 44 runs)
Re-uploading adds higher harmonics, so the zero-rotation identity becomes a sum of products. Extend
effective order to re-uploaded circuits, pre-register the ordering for 4 layouts, and run them. Many
recent QML architectures use re-uploading, so this extends the result to them.

### B4. A third dataset (≈ 60 runs)
Use SVHN, which is harder than MNIST, real-image, 10 classes and fits the 8-dimensional bottleneck.
Fashion-MNIST is a cheap fallback. Run linear, ring-free, default, pairs and last-ring heads at one
size, with the ordering pre-registered. If time allows, add EuroSAT, which is common in QML papers.

### B5. A second pretrained backbone (≈ 40 runs)
Use MobileNetV3 or EfficientNet-B0, which are light enough for the Mac, with the same heads and the
matched-update protocol at 4,000 images. This responds to the "one pretrained ResNet-18" limitation.
